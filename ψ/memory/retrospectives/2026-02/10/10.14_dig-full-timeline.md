## Honest Feedback

**Friction 1: Path encoding broke the dig.** The /rrr --dig skill's Python script encodes `pwd` with a sed command that produces `--Users-nat-Code-github.com-...` but the actual directory uses `github-com` (hyphen, not dot). Cost 10 minutes of debugging. The skill should just list directories matching a pattern instead of computing the path.

**Friction 2: Worktree sessions aren't discoverable.** The script only looked in the main project dir. SHRIMP has three project directories (main, wt, wt-1). 55 of 67 sessions were in wt-1. Without manual discovery, the dig would have found 12 sessions and missed the entire infrastructure story. The /rrr --dig skill needs worktree awareness.

**Friction 3: Post IDs are ephemeral.** Some Moltbook posts returned "Post not found" — either deleted by the platform or expired. The archive JSON files don't store the post UUID, so there's no way to reconstruct the mapping. Should store `{post_id, title, created_at}` in the archive filename or a manifest.

## Lessons Learned

1. **Worktrees create parallel histories that session logs can reconstruct.** Git log shows commits but not the conversation, debugging, and dead ends. Session JSONL files are the complete record.
2. **The /rrr --dig path encoding is fragile.** Dots in paths (github.com) break the sed-based encoding. Need a more robust approach.
3. **67 sessions in 11 days = ~6 sessions/day average.** The busiest day (Feb 02) had 21 sessions — all auth debugging. This is the cost of distributed systems.
